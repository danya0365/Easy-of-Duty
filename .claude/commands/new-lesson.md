สร้าง spec บทเรียนใหม่ตาม convention ใน `.claude/memory/MEMORY-GUIDE.md` โดยหัวข้อคือ: **$ARGUMENTS**

ทำตามขั้นตอนนี้:

1. อ่าน `docs/one-prompt-playbook.md` ส่วนที่เกี่ยวก่อน — บทเรียนใหม่ต้องต่อกับ playbook ไม่ใช่พูดซ้ำหรือขัดกันเอง
2. แปลงชื่อเป็น kebab-case → เขียนไฟล์ `.claude/memory/course/<slug>.md`
3. frontmatter มาตรฐาน (`type: module`, `status: active`, `scope: course`, `updated` = วันนี้)
4. โครง spec ของบทเรียน:
   - **จุดสอน (1 ประโยค)** — นักเรียนจะทำอะไรได้หลังจบบทนี้
   - **Mechanism ที่ต้องอธิบาย** — *กลไก* ที่ทำให้มันทำงาน ไม่ใช่ขั้นตอนคลิก (พี่สนใจกลไกเสมอ)
   - **หลักฐาน/ตัวเลขที่ต้องมี** — อ้างไฟล์จริงใน repo (`ARCHITECTURE.md`, `tools/*.mjs`, ตัวเลขใน `README.md`)
     ถ้าบทนี้อ้างต้นทุน ต้องบอกว่าเป็น "วัดจริง" หรือ "ประมาณ"
   - **LAB ที่พิสูจน์ได้** — งานเล็กที่มี gate ตรวจได้เอง (ถ้าไม่มี gate ก็ไม่ใช่ LAB ของคอร์สนี้)
   - **กับดักที่นักเรียนจะเจอ** — พร้อมวิธีสังเกตว่ากำลังติดกับดักนั้น
   - **ระดับผู้ฟัง** — audience ผสม บางคนไม่เคยใช้ Claude Code เลย ต้องมีทางไล่จากพื้นเข้าลึก
5. เตือนตัวเองเรื่อง framing: ขายว่า *"AI ที่รู้ว่างานตัวเองยังไม่ดีพอ"* **ห้าม** ขายว่า *"prompt เดียวได้เกม AAA"*
   (เกมอ้างอิงได้ 5.05/10 และแพ้ CoD จริงทุก blind A/B — ความซื่อตรงนี้คือจุดขาย)
6. เพิ่ม pointer 1 บรรทัดใน section **Course** ของ `.claude/memory/MEMORY.md`
7. สรุปกับพี่ว่าสร้างไฟล์ไหน + เตือนถ้า MEMORY.md ใกล้ 150 บรรทัด

> อยาก spec **subsystem ของเกม** (ไม่ใช่บทเรียน)? เขียนลง `.claude/memory/modules/<id>.md` แทน
> โครง: หน้าที่/ขอบเขต · interface กับ `ctx` · deps · ปมที่ต้องระวัง · gate ที่ต้องผ่าน
